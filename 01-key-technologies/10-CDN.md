## What is a CDN and when should you use it?

- A CDN, or Content Delivery Network, is a network of servers spread across the world that stores the content close to users.
- Instead of every user downloading content from your main server:

  ```text
  User in India -> Origin server in the US
  ```

- A CDN makes it:

  ```text
  User in India -> Nearby CDN server in India/Singapore
  ```

- This makes content load faster.
- CDNs work by caching content closer to users.

#### Cloudflare, Akamai, and Amazon CloudFront are common examples of CDNs

- CDNs are commonly used for images, videos, thumbnails, JavaScript files, static HTML, etc.
- Usually, with a CDN, the flow is:

  ```text
  User -> DNS -> CDN -> Load Balancer -> App Servers -> Database/Object Storage
  ```

- For static content:

  ```text
  User -> DNS -> CDN -> Response
  ```

- For dynamic API calls:

  ```text
  User -> DNS -> CDN -> Load Balancer -> App Server
  ```

#### CDN vs Cache

- A CDN is a type of cache, but geographically distributed.
- Redis cache: near the server, usually near the backend, for app/database data.
- CDN cache: near users, for static/media/web content.

#### CDN is mainly used for static content but can also be used for dynamic content

- Dynamic content is generated by the backend, but it can still be cached if it is the same for many users and okay to be slightly stale.
- For example, an API request to a page like `GET /products/iphone15` is dynamic because the backend may generate it using the product name, price, images, reviews, availability, and recommendations. The CDN can cache the generated HTML or API response for a short period of time.
